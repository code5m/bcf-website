# 同频：自托管部署和运营交付

**状态：可在自有服务器执行的部署包，未实际对公网开放。**

## 首次安装
1. 拥有可管理的 Linux 服务器、DNS 和域名，在 DNS 将域名指向服务器，允许 TCP 80/443。安装 Docker Engine 和 Docker Compose。
2. 复制配置文件：cp .env.example .env。
3. 设置 TONGPIN_DOMAIN；运行 openssl rand -hex 32 生成强随机 TONGPIN_ADMIN_TOKEN。不要把 .env 提交 GitHub。
4. 在服务器执行 docker compose up -d --build。Caddy 通过域名自动申请 TLS。
5. 访问 https://域名/tongpin/；后台审核 https://域名/tongpin/admin.html。
6. 通过 GET /api/social/health 核验服务可用、浏览器测试注册/登录及举报；未完成法务和运维审核前不可公开招募用户。

## 数据归属与备份
- 私人收藏库默认在浏览器 IndexedDB，不自动上传服务。
- 社交数据写入服务器的 social.sqlite（Node.js 24 内置 SQLite，WAL）；运行目录使用具名 Docker 卷 tongpin_runtime。
- SQLite 热备份需使用 SQLite 官方 backup API；否则先停服务再复制数据库和 WAL/SHM，不可运行中直接仅复制主数据库。
- 正式使用需制定备份留存和请求删除的清理策略。删除账户仅移除当前数据状态，离线备份还需独立清理。
- 社交消息未端到端加密，服务运营者技术上能够读取；必须真实告知用户。

## 运营治理
- 私人资料默认不可被发现，只有主动公开的收藏进入匹配。
- 举报进入人工队列，管理员密钥控制审核；可以标记处理、驳回或临时封禁7天。
- 生产仍需增加实名/邮箱验证（按实际法律与风险）、验证码或防机器人、申诉、每日审计、滥用阈值、安全测试、数据保护评估、内容合规和事故响应。

## 没有实际凭据不能自动完成的外部动作
- 真实服务器、域名和 DNS；Android 正式签名及 Play Console 发布；Apple Developer/签名/TestFlight/App Store 发布；商业主体、支付商户及法域审批。
- GitHub Actions 产出的 Android debug APK 与 iOS simulator 包仅证明开发/测试版本构建成功，不代表正式应用商店包，也不能用于公网上线安全背书。

## 内测邀请
生产 Docker 配置默认 TONGPIN_INVITE_ONLY=1。首次部署由管理员在 /tongpin/admin.html 生成一次性邀请码（7天有效），由邀请的成年人注册；禁止无邀请码公开注册。发送邀请码前需要核实受邀用户身份与同意政策。管理员报告列表可标记、驳回或暂停被举报账号，仍需要真实的人负责管理。

## 已有 BFC 工作台连接说明
本仓库原有首页是独立静态网站。自托管 Compose 默认只启动同频社交 API；完整 BFC 业务数据和进度 API 仍由原 bfc-backend / bilibili-favorites-workbench 提供，必须依照原有所有者会话和隐私边界单独接入。不要将 BFC 个人收藏库存公开代理给任何匿名访客。


## 上线边界与安全说明（2026-11-17）
- 生产环境拒绝本机 BFC 备份代理接口；仅非生产、本机回环环境支持用户主动导入。
- 社交 API 和旧 BFC 专题工作台并非同一个数据服务，个人收藏不可公开代理。
- 结伴学习仅在双方成为好友后开放，服务器只存储自愿填写的学习目标和双方打卡记录。
- 缺少生产多租户架构、邮箱/手机账户验证、消息推送、支付、签名分发及正式内容治理，不应把测试通过称为已正式商业化。


## 四阶段加固：可执行备份与恢复演练
- 使用 Node.js 24 在线备份：node scripts/backup-social.mjs runtime/social/social.sqlite ./backups/social-YYYY-MM-DD.sqlite。使用 SQLite 官方备份 API，并验证完整性、拒绝覆盖旧文件。
- 恢复之前先停止社交服务，在独立目录验证备份：node scripts/restore-social.mjs ./backups/social-YYYY-MM-DD.sqlite ./recovered/social.sqlite。该命令拒绝覆盖已存在的目标数据库，必须比对数据后才能受控切换。
- npm test 包含旧 JSON 和 SQLite 到规范化表的迁移以及在线备份恢复演练。自动化只证明样例场景，不代替实际生产环境恢复测试。
- 历史数据通过事务迁移成功后，删除该应用目录里的 social.json 及 social.json.migrated。额外的独立备份还需要运维设置保留期限和销毁策略。
- 生产必须设置 HTTPS 域名、管理员密钥、邀请码注册；社交消息没有端到端加密。
- 私人收藏不自动上传云端；Web/Android 使用版本化 JSON v3，iOS 原生可导入该数据，必要时用户主动迁移。不能将它描述成自动多端同步。
- 账号恢复使用8个一次性恢复码，须用户登录后本人生成并安全保存；全部丢失的情形仍无邮箱验证式找回。
- 举报与申诉需人工审核；负责人应设定响应时限、权限和数据保留策略，操作审计记录不能替代人工值班。
- 消息以50条游标分页读取，前台轮询；移动系统推送尚未实现。
- 公共域名、Android 正式签名、Apple 真机发行、应用商店审核和支付通道仍需外部合法账号与凭据。


## 2026-11-17 复审后数据与发行安全加固
- Web/Swift 用共享的 tongpin/tests/fixtures/private-v3.json 进行数据契约验证。缺少橱窗草稿 URL 也能恢复；数字进度和旧 BFC 进度对象均需兼容。npm test 校验 1,200 条私密收藏备份往返。
- 用户删除私人视频，旧导入撤销快照在同一 IndexedDB 事务中失效，不得重新生成已删除的私人笔记。删除本机记录不影响 B站收藏。
- iOS 重复新增原 BV 视频保留作者、旧笔记、专题、来源文件夹、完成状态及进度；进度合并允许更新至新数值。
- SQLite 正常业务事务不再读取整份聊天消息表；账户删除的消息清理位于同一个 SQLite 写事务中。登录签发新会话之前复核密码版本及最新封禁状态。
- 在线 SQLite 备份与恢复使用同目录临时文件和硬链接原子独占创建；并发竞争时失败，不覆盖已有备份。生产恢复之前仍必须停止服务并核验备份。
- 本机 health 检查真实写入读取数据库；公网 health 仅检验可读，避免通过匿名 GET 持续写入耗尽磁盘。
- Android 离线页面与用户明确选定的 HTTPS 社交服务均以精确 Origin 白名单接入系统 JSON 保存通道，支持私人及社交账户 JSON 导出。Android 真机仍需验证设备兼容和文件权限。
- GitHub Actions 生成的 Android debug APK 可能每次使用不同的临时调试签名。更新前必须导出并检查私人收藏备份；切勿在唯一副本未备份时卸载旧 APP。正式无缝升级需要稳定的发行签名与账号。
- iOS 当前仍为模拟器构建，真实 iPhone、正式签名商店发行、支付系统及运维治理不应声称已通过。自动化测试不等同于真实商业上线验收。
