# 同频 / Tongpin — BFC 收藏交友 MVP

当前实现放在 code5m/bcf-website 的 **feature/tongpin-social-mvp-20261116** 分支；不影响原有 BFC 数据管理入口。

## 本地启动

要求 Node.js 24+，**无需 npm install**。

```sh
npm start
# http://127.0.0.1:4173/tongpin/
```

```sh
npm test
```

Web 可作为 PWA 安装；Android 调试 APK 和 iOS Simulator 包由 GitHub Actions 生成。未提供正式签名 APK / iOS 真机 IPA，也未实际部署公共服务器。

## 已实现（设计范围）
- IndexedDB 私人收藏：手动添加、编辑、搜索、标签、JSON 导入/导出、去重与分页；隐私数据不通过社交 API 上传。
- 用户明确挑选最多 20 条公开收藏，编辑后主动发布。私人笔记、原文件夹和剩余收藏不在公开数据结构中。
- 社交账户：年满 18 岁声明、账号密码加盐哈希、HttpOnly SameSite Cookie、同源写入约束。
- 公开资料默认不可发现。双方发布收藏、公开个人资料后可按共同 BV、兴趣主题、公开标签匹配。
- 双向同意的好友申请、好友文字消息、拉黑、举报、社交账号删除。
- 离线缓存静态前端资源；无 B站账号网络读写，绝不尝试绕过 HTTP 412。
- 使用内置 SQLite WAL 进行事务性持久化，但业务状态仍整体序列化在一个数据行内，适用于单实例/受控测试，尚不是面向大规模公众的多租户架构。

## 与 BFC 原项目的关系
- / 保留原 BFC 专题学习入口； /tongpin/ 新增社交产品。
- 支持导入用户手动导出的 BFC JSON 备份；不会自动读取私有 BFC 服务端库存。
- 社交功能使用独立 runtime/social 数据目录，不修改 BFC 4198 的账号权限及收藏夹流水。
- 可设置 TONGPIN_DATA_DIR 自定义社交数据目录，必须保持私密、限制操作系统访问权限。
- 在本地开发时仅绑定 127.0.0.1，默认端口 4173。

## 验收范围与尚未完成
1. Node.js 运行 `npm test`：校验私有数据过滤、共同兴趣匹配、默认不公开、交友邀请、消息权限、拉黑和删除。
2. 手动端到端：导入 JSON → 私人收藏 → 精选草稿 → 注册 → 发布 → 开启发现 → 第二账号匹配 → 申请 → 接受 → 聊天。
3. PWA 离线：联网访问后断网刷新客户端，社交 API 离线时不应假装在线；私人收藏应继续可用。
4. 尚未完成：大规模生产多租户数据库、邮箱验证、找回密码、实际举报审核人员运营、消息端到端加密、规模化风控、APP 商店签名和分发。GitHub Actions 已覆盖浏览器端到端回归，不能替代真实硬件兼容测试。
5. 严禁将测试演示用户或个人 B站收藏清单写入 GitHub。
